   107→Agent: Main Agent (Super Z)
   108→Task: Perbaiki error "Unauthorized" di apiFetch saat reload halaman
   109→
   110→Work Log:
   111→- Investigasi penyebab: race condition antara Zustand persist hydration dan API call pertama
   112→  * Zustand persist hydrate dari localStorage secara ASYNC
   113→  * Komponen (DashboardMenu, MainShell) langsung call API di useEffect sebelum store selesai hydrate
   114→  * Akibatnya: useAuthStore.getState().user masih null → x-user-id header tidak terkirim → API return 401
   115→- Solusi 1: Tambah flag hasHydrated ke auth store
   116→  * Tambah state hasHydrated: boolean (default false)
   117→  * Gunakan onRehydrateStorage callback untuk set hasHydrated=true setelah hydrate selesai
   118→  * Tambah method setHasHydrated
   119→- Solusi 2: Update page.tsx untuk tunggu hydration
   120→  * Tampilkan loading screen dengan spinner selama hasHydrated=false
   121→  * Hanya render LoginPage atau MainShell setelah hasHydrated=true
   122→  * Ini mencegah komponen menu render dan call API sebelum session ter-load
   123→- Solusi 3: Update MainShell dengan guard hasHydrated
   124→  * Tambah hasHydrated ke useAuthStore selector
   125→  * useEffect hanya fetch menus jika hasHydrated && user
   126→  * Return null jika !hasHydrated atau !user
   127→- Solusi 4: Update DashboardMenu dengan defensive guard
   128→  * Hapus non-null assertion (!), ganti dengan optional
   129→  * Tambah if (!user) return di useEffect
   130→  * Tambah if (!user) return <LoadingState> di render
   131→- Solusi 5: Update api-client.ts untuk handle 401 gracefully
   132→  * Jika API return 401, auto-logout dan reload ke login page
   133→  * Tampilkan pesan "Session tidak valid. Silakan login kembali."
   134→  * Ini mencegah error unhandled di console
   135→- Verifikasi via Agent Browser:
   136→  * Login sebagai DPN → dashboard tampil dengan data ✓
   137→  * Reload halaman → tidak ada error 401 di console ✓
